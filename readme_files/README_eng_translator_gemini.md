# eng_translator_gemini.py — переводчик EN→RU через Google Gemini

Перевод новелл с английского на русский через Gemini API (`GEMINI_API_KEY` в `.env`).

## Режимы перевода

- **Последовательный** (по умолчанию) — чанк за чанком, контекст из хвоста
  предыдущего перевода (или из конспектов при `--summaries`).
- **`--parallel N`** — N потоков одновременно. Возможен благодаря пре-пассу
  конспектов: контекст сюжета берётся из конспектов исходника, а не из
  предыдущего перевода, поэтому чанки независимы.
- **`--batch`** — Gemini Batch API: все чанки одним заданием, **цена −50%**.
  Задание может выполняться до пары часов (обычно быстрее); прогресс
  сохраняется, при сбое можно продолжить `--resume --parallel N`.

## Контроль качества (автоматический, на каждом чанке)

1. **Пунктуация/английский**: механические фиксы кавычек и тире бесплатно
   регулярками; корректирующий вызов дешёвой модели — только если что-то осталось.
2. **Линтер полноты**: отношение длин перевод/оригинал и числа абзацев;
   при подозрении на пропуск — один ретрай с жёсткой инструкцией.
3. **ЛитРПГ-шаблоны** (`litrpg_glossary.json`): фиксированные переводы статов
   (Level→Уровень, Strength→Сила...) — подмешиваются в глоссарий чанка и
   детерминированно заменяют уцелевший английский в выводе.
4. **Матрица ты/вы** из глоссария: когда оба персонажа пары в чанке, модель
   получает явное указание, кто к кому на «ты», кто на «вы».
5. **Детектор дрейфа транслитерации** (после перевода): находит «Поварит»
   при каноне «Паварит» по расстоянию Левенштейна и частотам — то, что глазами
   в 500 главах не найти.

## Чем отличается от eng_translator.py (GPT-версии)

1. **Меньшие чанки по умолчанию (3000 символов вместо 4000).** На длинных чанках
   модель к концу «забывает» правила из системного промпта и начинает использовать
   английскую пунктуацию. Меньший чанк = правила всегда «рядом».
2. **REMINDER-блок.** Краткая выжимка критических правил (русская пунктуация,
   тире в диалогах, «ёлочки», ноль английских слов) дублируется в **конце** каждого
   запроса, сразу после текста — именно конец промпта модель помнит лучше всего.
3. **Автопроверка каждого чанка.** После перевода текст проверяется на:
   - английские кавычки `"..."` / `“...”`;
   - дефис/среднее тире вместо длинного тире в диалогах;
   - непереведённые английские слова (кроме рангов SS/S/A, HP/MP/XP и брендов).

   Найденные нарушения исправляются корректирующим запросом к модели, затем
   механическим дофиксом (замена кавычек и тире регулярками).
4. **Авто-подхват глоссария.** Если рядом лежит `<имя_файла>_glossary.json`, он
   подключается сам (отключить: `--no-glossary`).
5. **Итоговый отчёт** — сводка оставшихся нарушений по всем чанкам.

## Использование

```bash
python3 eng_translator_gemini.py book.docx
python3 eng_translator_gemini.py book.epub -o перевод.docx
python3 eng_translator_gemini.py book.docx --model gemini-2.5-flash   # дешевле
python3 eng_translator_gemini.py book.docx --glossary glossary.json
python3 eng_translator_gemini.py book.docx --resume                   # после прерывания
```

## Рекомендуемый пайплайн

```bash
# 1. Собрать глоссарий (частотный: минимум 2 появления, сортировка по частоте)
python3 glossary_builder.py book.epub -o book_glossary.json

# 2. Отредактировать глоссарий руками (проверить транслитерации)
code book_glossary.json

# 3. Перевести (глоссарий подхватится сам, если назван book_glossary.json)
python3 eng_translator_gemini.py book.epub -o перевод.docx

# 4. Добить остатки английского, если отчёт показал нарушения
python3 fix_english_remnants.py перевод.docx
```

## Экономия токенов

Скрипт спроектирован так, чтобы новелла стоила центы, а не десятки долларов:

1. **Модель по умолчанию — `gemini-2.5-flash`** ($0.30/$2.50 за 1M токенов).
   Pro (`--model gemini-2.5-pro`) в ~4 раза дороже — включай только если flash
   не устраивает по качеству на конкретной новелле.
2. **Thinking отключён** (`thinking_budget=0` для flash, минимум 128 для pro).
   Thinking-токены билятся по цене вывода — на переводе это была бы главная
   скрытая статья расходов. Вернуть размышления: `--thinking-budget -1`.
3. **Корректирующий запрос — только когда нужен.** Сначала текст чинят
   бесплатные регулярки (кавычки, тире); модель вызывается только если после
   них остались нарушения. И всегда — дешёвый flash, даже если переводит pro.
4. **Глоссарий фильтруется по чанку** — в промпт попадают только термины,
   которые реально встречаются в текущем куске текста.
5. **Фактический чек в конце** — после перевода печатается реальный расход
   токенов по каждой модели и итоговая стоимость в долларах.

Ориентир: новелла на 2,5 млн символов (~490 глав) на flash ≈ **$2–3**,
на pro ≈ $10–12. Для сравнения, GPT-версия (gpt-5.1 + вторая проходка
форматирования) на том же объёме — порядка $70–100.

Глоссарий тоже можно собирать дешёво: `python3 glossary_builder.py book.epub
--model gpt-5-mini` — извлечение имён простая задача, мини-модель справляется.

## Глоссарий и частотность

`glossary_builder.py` теперь считает, сколько раз каждая сущность (имя + алиасы)
встречается в тексте (`occurrences`):

- сущности с **меньше чем 2 появлениями отбрасываются** (`--min-occurrences`, по
  умолчанию 2; `0`/`1` — отключить);
- глоссарий **сортируется по частоте** (частые → редкие), и при переводе самые
  важные имена оказываются первыми в промпте;
- в режиме `--from-raw` (без исходного текста) частота приближённо считается по
  числу чанков, где сущность упоминалась.

После консолидации выполняется **Phase 3: cross-batch dedup** — финальная
проходка слияния дублей. Консолидация видит записи батчами по 50, поэтому
«Paw» и «Pawarit» из разных батчей она слить не могла. Phase 3 отправляет
модели только пронумерованные списки имён (без заметок — дёшево, один вызов
на категорию), получает группы «это один и тот же персонаж» и сливает их
локально: имена дублей уходят в алиасы, переводы — в alternatives, род
подтягивается из той записи, где он определён. Отключить: `--no-dedup`.

Дополнительно — бесплатные проходы кодом (без токенов):

- **Род по статистике местоимений**: для каждого персонажа считаются he/his
  против she/her в окне после каждого упоминания имени по всей книге (окно
  обрезается на упоминании другого персонажа). Уверенный сигнал перекрывает
  догадку модели — надёжно даже там, где в чанке местоимений не было.
- **Склоняемость по правилам морфологии**: мужское имя на согласную склоняется
  (в глоссарий пишется готовый пример род. падежа: «Паварит, р.п. Паварита» —
  модель подражает примеру надёжнее, чем применяет правило), женское на
  согласную — несклоняемое (Элис), на -а/-я — склоняется у всех, на прочие
  гласные — несклоняемое (Гирё).

И **Phase 4: матрица ты/вы** — по диалоговым цитатам топ-10 персонажей один
вызов модели решает, кто к кому обращается на «ты», кто на «вы» (включая
асимметрию и перелом по сюжету). Секция `relations` в глоссарии; переводчик
подставляет её в промпт, когда оба персонажа пары встречаются в чанке.
Отключить: `--no-relations`.
